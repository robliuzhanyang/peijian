# 鑫戩配件商城 · 前后端数据与 API 接入说明

> 适用工程：`peijian-pc`（PC，端口 8002）、`peijian-h5`（H5，端口 8003）
> 技术栈：Vue 2.6 + Vue Router 3（hash）+ Vuex 3 + Axios
> 本文说明当前前端的数据来源、接口边界，以及接入真实后端时的推荐做法。

---

## 1. 当前数据架构

```
页面（views/*.vue）
  ├─ 目录数据：store.dispatch('bootstrap')
  │    └─ productsApi.list / categories / packages  → src/mock/catalog.json
  ├─ 交易后业务：businessApi.*
  │    ├─ mock 模式：直接读 Vuex state（合同/发票/售后/企业/消息/积分等）
  │    └─ api  模式：请求 VUE_APP_API_BASE_URL + 路径
  ├─ 一站式选购：oneStopApi.catalog / calculate / saveDraft
  │    └─ mock 模式：src/mock/oneStopCatalog.js
  └─ 本地持久化：localStorage（见第 4 节）
```

两端代码结构一致，页面文件名与路由基本一一对应；**接口层与 store 需两端同步修改**。

关键文件：

| 文件 | 作用 |
| --- | --- |
| `src/config/env.js` | 环境解析（env / dataMode / apiBaseUrl）与 token 读写 |
| `src/api/http.js` | Axios 实例、token 注入、响应解包与 401 处理 |
| `src/api/index.js` | 商品、订单、鉴权、交易后业务接口适配层，mock/api 切换入口 |
| `src/api/oneStop.js` | 一站式选购接口适配层（同样支持 mock/api） |
| `src/store/index.js` | 全局状态、前端 CRUD、localStorage 持久化 |
| `src/mock/catalog.json` | 商品、订单、合同、发票、售后、消息、积分等演示数据 |
| `src/mock/oneStopCatalog.js` | 一站式选配目录与部件商品 |
| `src/mock/regions.js` | 省市区数据（地址级联与粘贴解析） |
| `src/domain/*` | 价格、商品字段、地址解析、报价单、一站式业务规则 |
| `src/router/index.js` | 路由表；PC 的「我的」为 `/user` 嵌套子路由 |
| `public/config.js` | 部署期运行时配置（可覆盖 env / apiBaseUrl / dataMode） |

## 2. 环境变量与正式 / 测试分流

两端通过 `.env.*` 与 `public/config.js` 两级配置区分环境，**正式环境不再使用 mock**。

| 文件 | H5 | PC |
| --- | --- | --- |
| `.env.development` | `ENV=development`，`MODE=mock`，`/api/h5` | `ENV=development`，`MODE=mock`，`/api/pc` |
| `.env.sit` | `ENV=sit`，`MODE=api`，`/api/h5` | `ENV=sit`，`MODE=api`，`/api/pc` |
| `.env.production` | `ENV=production`，`MODE=api`，`/api/h5` | `ENV=production`，`MODE=api`，`/api/pc` |

完整变量名：`VUE_APP_ENV`、`VUE_APP_DATA_MODE`、`VUE_APP_API_BASE_URL`。

### 2.1 配置解析优先级

`src/config/env.js` 按以下顺序解析（高 → 低）：

1. `public/config.js` 中的 `window.__XJ_CONFIG__`（部署后可直接改，无需重新构建）
2. 构建时的 `.env.*`
3. 默认值：`mock` + `/api/h5`（PC 为 `/api/pc`）

```js
// public/config.js —— 随 dist 发布，按部署环境修改
window.__XJ_CONFIG__ = {
  env: "sit",                                   // sit | production
  apiBaseUrl: "https://sit-api.example.com/api/h5", // 留空则用构建变量
  dataMode: "api",                              // 正式/测试必须为 api
};
```

> 同一份构建产物可通过修改 `config.js` 切换测试/正式接口地址，避免发错环境。

### 2.2 命令

```bash
npm run serve        # 本地开发（mock）
npm run serve:sit    # 本地连测试后端调试
npm run build:mock   # 静态演示包（不依赖后端）
npm run build:sit    # 构建测试环境包
npm run build:prod   # 构建正式环境包
```

- `VUE_APP_DATA_MODE=mock`：不请求后端，使用本地 JSON + Vuex。
- `VUE_APP_DATA_MODE=api`：走 `src/api/http.js` 的 axios 实例，请求 `API_BASE_URL` 下的接口。
- 启动后控制台会输出 `env / data / api`，便于确认当前环境。
- 网关需把 `/api/h5`、`/api/pc` 分别转发到对应服务；测试与正式使用各自域名或网关。

本地开发若后端不在同源，需在 `vue.config.js` 增加代理（当前未配置）：

```js
devServer: {
  port: 8003, // PC 为 8002
  proxy: {
    "/api": {
      target: "http://127.0.0.1:8080",
      changeOrigin: true,
    },
  },
}
```

> 注意：项目使用 hash 路由与相对路径 `publicPath: './'`，静态部署无需 rewrite；
> 但接口地址是**绝对路径** `/api/...`，子目录部署时需由网关按前缀转发。

## 3. 接口清单（建议契约）

统一约定：

- 金额字段统一为**分**（`*Fen`），前端用 `money()` 转元展示。
- 时间统一 `YYYY-MM-DD HH:mm`（日期字段可为 `YYYY-MM-DD`）。
- 列表接口返回数组；需要分页时返回 `{ items, total, page, pageSize }`。
- 建议统一响应 `{ code, message, data }`，由 axios 拦截器解包 `data`。
- 资源 id 由后端生成；前端当前使用 `XJ/HT/INV/AS + Date.now()` 仅为演示。

## 4. 前端状态与本地持久化

`src/store/index.js` 中 `persist()` 的白名单就是当前落盘范围：

```
cart, orders, favorites, addresses, selected, selectedScheme,
contracts, invoices, aftersales, companies, currentCompanyId,
messages, profile, points, pointsLedger, authStatus, loggedIn, seeded
```

- H5 键：`xinjian-h5-v3`；PC 键：`xinjian-pc-v3`（两端隔离）。
- `seeded=true` 表示种子已合并；修改 mock 数据结构后需清空该键，否则旧数据会继续沿用。
- 接后端后，交易类与账号类数据应改为“接口为准”，逐步从 `persist()` 中移除；
  购物车、当前选配方案等纯交互状态可以继续本地保存。

### 4.1 本地 mutation → 建议接口

| 前端 mutation | 当前行为 | 后端接口 |
| --- | --- | --- |
| `submitOrder` | 生成订单、清空购物车 | `POST /orders` |
| `setOrderStatus` | 支付/核款状态 | `POST /orders/:id/pay` |
| `cancelOrder / confirmReceipt / remindShip` | 订单状态流转 | 对应动作接口 |
| `createContract / signContract` | 本地生成/签署 | `POST /business/contracts`、`/:id/sign` |
| `createInvoice / resubmitInvoice` | 本地开票申请 | `POST /business/invoices` |
| `createAftersale / cancelAftersale` | 本地工单 | `POST /business/aftersales` |
| `addAddress / updateAddress / removeAddress / setDefaultAddress` | 本地地址簿 | 地址 CRUD |
| `registerCompany / switchCompany` | 企业列表与当前企业 | 企业注册、切换 |
| `exchangePoints` | 扣积分 + 写流水 + 写消息 | `POST /business/points/exchange` |
| `markMessageRead / markAllMessagesRead` | 本地已读 | 消息已读接口 |
| `pushMessage`（内部） | 业务动作后本地生成消息 | 由后端在业务事件中生成 |

## 6. 请求封装与鉴权建议

`src/api/http.js` 已内置请求/响应拦截器：自动附带 `Authorization: Bearer <token>`、解包
`{ code, message, data }`、401 清除 token 并回到登录页。以下为等价示意，便于按后端规范调整：

```js
http.interceptors.request.use((config) => {
  const token = localStorage.getItem("xinjian-token");
  if (token) config.headers.Authorization = "Bearer " + token;
  return config;
});

http.interceptors.response.use(
  (res) => {
    const body = res.data;
    // 后端统一返回 { code, message, data } 时解包；code 非 0 抛错
    if (body && typeof body.code !== "undefined") {
      if (body.code !== 0) return Promise.reject(new Error(body.message));
      return body.data;
    }
    return body;
  },
  (err) => {
    if (err.response && err.response.status === 401) {
      localStorage.removeItem("xinjian-token");
      location.hash = "#/login";
    }
    return Promise.reject(err);
  }
);
```

其他约定：

- **登录态**：当前 `login` mutation 仅切换本地布尔值，需替换为真实登录接口并保存 token。
- **权限**：企业与认证状态相关的按钮（报价、合同、开票）应以后端权限为准。
- **幂等**：下单、支付、合同生成、开票、售后提交、积分兑换需支持幂等键，避免重复提交。
- **上传**：合同盖章件、售后凭证使用 `multipart/form-data`，返回文件 URL 后再提交业务表单。
- **分页**：PC 商品列表为 `listQuery { q, cat, page, pageSize }`；后端应返回 `{ items, total }`。
- **错误提示**：页面统一通过 `setNotice` 展示错误，接口层错误信息应可直接展示给用户。

## 7. 必须下沉到后端的业务规则

以下逻辑目前在前端（`src/domain` 与 `src/store`），接后端时需要服务端兜底：

1. 价格与优惠：商品价、套餐折扣率、破套后的组合价、订单合计。
2. 库存与可售：`buyable / stock / sku` 校验，下单时再次校验。
3. 订单状态机：待付款→待核款/已付款→待发货→运输中→待收货→已完成，以及取消规则。
4. 单号生成：订单 `XJ`、合同 `HT`、发票 `INV`、售后 `AS` 应由后端统一生成。
5. 合同/发票/售后的幂等与状态流转。
6. 积分：余额校验、月限购、扣减与流水写入必须原子完成。
7. 消息：由业务事件生成（支付、合同、开票、售后、兑换、认证），而不是前端 `appendMessage`。
8. 企业权限：当前企业、可切换企业、认证状态对应的操作权限。
9. 地址默认值：保证唯一默认地址与删除后的补位。

前端保留的部分：地址文本解析（`addressParse.js`）、报价单 PDF/图片导出、选配联动与破套确认交互。

## 8. 建议接入顺序

1. **只读**：商品/分类/套餐 → 订单/合同/发票/售后/地址/消息/积分列表与详情。
2. **登录与资料**：登录、token、profile、企业列表与切换、认证进度。
3. **写操作**：下单、支付、合同生成/签署、开票、售后、地址 CRUD、积分兑换。
4. **清理本地态**：移除 `SEED` 合并、对应本地 mutation 与 `persist()` 字段；
   保留购物车、选配方案等纯前端状态。

## 10. 常见问题

1. **改了 mock 数据但页面没变**：localStorage 中 `seeded` 已存在，清理 `xinjian-h5-v3` / `xinjian-pc-v3` 后刷新。
2. **接口 404**：确认 `VUE_APP_API_BASE_URL` 与网关前缀（`/api/h5`、`/api/pc`）一致；本地开发需配置 proxy。
3. **跨域**：开发环境优先用 proxy；生产由同域网关转发，避免前端直连不同域名。
4. **登录后仍显示未登录**：当前登录态存于 localStorage 的 `loggedIn`，接真实接口后应改为 token 判断。
5. **金额出现小数误差**：接口与 store 统一用分，展示层再除 100。
6. **文件只有文件名**：当前合同盖章件、售后附件只记录本地文件名，需接入上传接口并保存 URL。
