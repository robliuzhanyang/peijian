# 鑫戩配件商城 H5 / PC 项目说明

## 1. 交付内容

- `peijian-h5/`：H5 独立 Vue 项目，包含完整源代码与已构建的 `dist/`。
- `peijian-pc/`：PC 独立 Vue 项目，包含完整源代码与已构建的 `dist/`。
- 两端均使用假数据，可直接浏览完整页面与交互；后续可在现有 API 适配层中接入真实接口，
  完整接口清单、数据模型与接入步骤见 [前后端接口对接说明.md](./前后端接口对接说明.md)。

## 2. 本次“一站式选购”调整

1. 原“方案一 / 方案二 / 方案三”统一调整为“立式方案 / 卧式方案 / 悬挂式方案”，并合并到同一个一站式选购页面。
2. 选型流程统一为 8 步：选择方案、机柜、铝件 5 件套、核心光学、激光器、打标控制、电脑套装、扩展配件。
3. 选择机柜后自动带出匹配的铝件 5 件套。
4. 铝件 5 件套可展开并单独微调立柱、光路、夹具板、定位条、电脑架。
5. 更换立柱后，会联动过滤可选光路。
6. 激光器会联动匹配控制器；控制器会影响扩展配件的兼容范围。
7. 视频振镜自带场镜，选中后不再重复选择独立场镜。
8. 每个选配步骤标题右侧增加“从配件商城选择”入口，点击后以弹框（H5 为底部抽屉）展示当前品类且兼容的商品。
9. 铝件 5 件套的商城弹框提供立柱、光路、治具板、定位条、电脑支架五个分类切换。
10. 从配件商城加入或更换商品时，立即弹出“破套重算”提醒；确认后仍保留一站式选购流程，但计价方式切换为“组合价”，即所选商城商品正价之和。
11. 页面下方持续展示当前清单；编辑某项时只展示同品类且兼容的商品。
12. 原 `/package` 地址保留，访问后兼容跳转到 `/diy?entry=package`。

## 4. 本地运行与构建

分别进入 H5 或 PC 项目目录执行：

```bash
npm install
npm run serve
```

- H5 默认地址：`http://localhost:8003`
- PC 默认地址：`http://localhost:8002`
- 如需更换端口：`DEV_PORT=9000 npm run serve`

生产构建：

```bash
npm run build:mock   # 静态演示包（本地假数据，不依赖后端）
npm run build:sit    # 测试环境包（走 /api/* 测试网关）
npm run build:prod   # 正式环境包（走 /api/* 正式网关）
```

构建结果输出到各项目的 `dist/`。项目使用 Hash 路由和相对静态资源路径，部署时可直接将 `dist/` 中的文件发布到静态服务器或任意子目录。

> 环境区分：`.env.development`（本地 mock）、`.env.sit`（测试 api）、`.env.production`（正式 api）。
> 部署后还可修改 `dist/config.js` 覆盖 `env / apiBaseUrl / dataMode`，无需重新构建。
> 详见 [前后端接口对接说明.md](./前后端接口对接说明.md) 第 2 节。

## 5. 一站式选购核心代码

以下相对路径在 H5、PC 两个项目中均存在：

| 文件 | 作用 |
| --- | --- |
| `src/views/diy.vue` | 一站式选购主页面；H5 与 PC 分别实现适配各自终端的布局 |
| `src/views/package.vue` | 旧套装地址兼容页，自动跳转到一站式选购 |
| `src/views/diy-confirm.vue` | 选配方案确认页，显示套餐价或破套后的一站式组合价 |
| `src/views/quote.vue` | 采购报价单页 |
| `src/mock/oneStopCatalog.js` | 方案、8 步流程、商品、兼容关系与价格假数据 |
| `src/api/oneStop.js` | 假 API 适配层，后续真实接口的主要替换入口 |
| `src/domain/oneStopMixin.js` | 选型、兼容过滤、自动带出、破套重算等共享业务逻辑 |
| `src/store/index.js` | 方案、商品、购物车等前端状态 |
| `src/router/index.js` | 全部路由与页面标题 |

## 7. 后续 API 对接说明

> 全量接口清单、请求/响应示例、数据模型、鉴权与分页约定、迁移顺序，见
> [前后端接口对接说明.md](./前后端接口对接说明.md)。以下为一站式选购的补充要点。

1. 优先修改 `src/api/oneStop.js`，将现有 Promise 假请求替换为 Axios 请求。
2. 商品与方案数据结构集中在 `src/mock/oneStopCatalog.js`，可作为后端接口字段参考。
3. 商品 ID、分类 ID 和兼容关系 ID 应保持稳定；页面联动依赖这些 ID。
4. 价格统一使用“分”为单位存储，页面展示时再转换为“元”，避免浮点计算误差。
5. 建议真实接口至少提供：获取方案与商品目录、计算/校验方案、保存选配草稿三个能力。
6. 后端应再次校验立柱与光路、激光器与控制器、控制器与扩展件等兼容关系，前端过滤只负责交互体验。
7. “破套重算”状态应随方案草稿一起提交，后端根据状态返回套餐价或商城正价合计。

## 8. 验证结果

- H5、PC 两个项目均已完成生产构建，`dist/` 已随源码交付。
- 一站式选购核心业务自动验证通过：三种方案、8 步完成度、步骤商城弹框、五件套分类切换、视频振镜自带场镜、立柱与光路联动、破套提醒、一站式组合价重算、确认页跳转。
- 构建无编译错误。原项目自带字体文件体积较大，因此构建工具会显示资源体积提示，不影响页面运行与部署。
